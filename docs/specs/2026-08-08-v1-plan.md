# outlook-scan v1 — project plan

Personal Go CLI that extracts inbox content from Microsoft Outlook for Mac
("New Outlook") via the macOS Accessibility (AX) API and writes it as
markdown + JSON files for consumption by Claude Code.

Single user, single account, single machine. Not a service, not a product.

Inspired by https://github.com/Arkya-AI/outlook-email-scanner (MIT, Python).
We reuse its architecture ideas (AX-tree navigation, scan loop, persistent
dedup, markdown output) but drop its freemium gating, multi-account support,
and UI-driving features, and fix its English-only heuristics.

## Why this approach (verified 2026-08-08)

- Target machine runs **New Outlook 16.109** (React-based client).
- The legacy `Outlook.sqlite` store is empty/stale → reading the local DB
  directly is not possible.
- AppleScript responds but its object model is backed by the same empty
  legacy store (0 accounts, 0 messages) → AppleScript route is dead.
- Microsoft Graph is out of scope by design (no tenant/IT involvement).
- Therefore AX-tree scraping is the only local extraction route. This is
  the same conclusion the upstream project reached.

## Architecture

```
cmd/outlook-scan/       CLI (stdlib flag; subcommands: dump, scan)
internal/ax/            cgo bindings to ApplicationServices AX API
internal/outlook/       tree navigation + email extraction (reader)
internal/scan/          scan loop, scroll, dedup, output writers
```

### internal/ax (cgo)

Thin, generic bindings — no Outlook knowledge:

- `Trusted()` — AXIsProcessTrustedWithOptions (permission preflight)
- `AppByBundleID(id)` — AXUIElementCreateApplication via PID lookup
- Element attribute getters: role, title, value, description, children,
  position, size, selected/visible rows
- `SetSelected(el)` — AXUIElementSetAttributeValue(kAXSelectedAttribute)
- `Press(el)` — AXUIElementPerformAction(kAXPressAction)
- Scroll: CGEventCreateScrollWheelEvent (no robotgo dependency; row and
  sidebar-folder selection go through AXSelected/AXPress first — a single
  synthesized CGEvent click at an AX-provided coordinate is the fallback
  only if that fails. Search-box typing stays out of scope, so no
  keyboard synthesis)
- Careful CFRelease discipline; every Copy* result released

Defined behind a Go interface so `internal/outlook` is testable with fakes.

### internal/outlook (reader)

Port of the upstream reader's navigation, with two deliberate changes:

1. **Locale-neutral navigation.** Upstream matches label text
   ("Inbox" in window title, "From: " prefixes, English month names,
   "Today/Yesterday"). This fails on a German UI ("Posteingang", "Von:",
   "Heute"). We navigate by AX role/structure (AXSplitGroup, AXTable,
   AXScrollArea, AXWebArea, AXOutline) and treat label text as opaque.
   Where text parsing is unavoidable (timestamp, sender), support both
   German and English patterns and always keep the raw string.
2. **No hardcoded child indices where avoidable.** Upstream uses fixed
   indices into AXChildren for Outlook 16.x. We search by role first and
   fall back to indices, and we log the actual tree shape on mismatch.

Extracted per email: subject, sender, recipients, timestamp (raw +
best-effort parsed), body text (via AXWebArea static texts), unread flag,
attachment filenames (extension heuristic).

**Folder navigation (in scope — threads span folders):** the sidebar is an
AXOutline; list its rows as folders and switch by setting AXSelected /
performing AXPress on a row (fallback: one CGEvent click at the row's
AX coordinates). Folder names are matched as opaque user-visible labels
("Archiv", "Gesendete Elemente"), so this stays locale-neutral. Single
account only, so no account disambiguation in the sidebar walk.

**Threads:** New Outlook's conversation view renders the whole thread —
including sent replies and archived parts — in the reading pane when one
message is selected. Phase 0 tests whether one AXWebArea read captures the
full visible conversation and whether collapsed items expand via AXPress.
If that works well, scanning Inbox + Archive + Sent Items per folder is a
complement, not the only route to complete threads.

### internal/scan

- Loop: visible rows → select → read → hash → dedup check → write file;
  scroll message list; stop on end-of-list (identical visible hash set),
  max-emails, or timeout. Same shape as upstream's controller.
- Dedup: normalized hash of sender+subject+timestamp persisted as JSON at
  `~/.outlook-scan/seen.json`.
- Output: one `YYYY-MM-DD-<slug>.md` per email plus a `.json` sidecar,
  under `~/outlook-emails/` (flag-overridable). A `manifest.json` per run
  with stats.

### CLI

- `outlook-scan dump [--depth N]` — pretty-print the Outlook AX tree.
  Built FIRST; it is the exploration/debug tool and the feasibility gate.
- `outlook-scan folders` — list sidebar folder labels for the account.
- `outlook-scan scan [--folder LABEL]... [--max N] [--out DIR]
  [--unread-only] [--reset-dedup]` — default folder: the currently open
  view; repeatable --folder scans several (e.g. Inbox, Archiv,
  Gesendete Elemente) in one run, output partitioned per folder.
- No config file in v1; flags only.

### Claude Code integration

A skill (SKILL.md) so "check my inbox" runs `outlook-scan scan` and reads
the markdown output. Written last, once the CLI is stable.

## Out of scope for v1

Multi-account discovery/switching, keyword search (requires typing into
the live UI — the flakiest part of upstream), date/sender filters
(Claude can filter the markdown itself), YAML config, license/pro
anything, website, CI. Folder switching is IN scope (threads span
Inbox/Archive/Sent), but via AX selection/press rather than upstream's
synthesized clicks.

## Phases

**Phase 0 — feasibility spike (~1 day). Go/no-go gate.**
Go module scaffold + `internal/ax` bindings + `dump` subcommand.
Milestones:
1. Dump the running New Outlook window tree; positively identify message
   table, rows, reading-pane header group, AXWebArea body, and the
   sidebar AXOutline.
2. Selection experiments: does AXSelected/AXPress work on (a) message
   rows, (b) sidebar folder rows? Does the reading pane's conversation
   view expose the full thread in one read; do collapsed items expand
   via AXPress?
If the tree doesn't expose these, stop and reassess (with the actual
dump in hand) before writing any more code.

**Phase 1 — working scanner (~1–2 days).**
Reader navigation + scan loop + scroll + dedup + markdown/JSON output.
Milestone: `outlook-scan scan --max 30` produces correct files from the
real inbox, run twice → second run skips all as duplicates.

**Phase 2 — folders (~0.5–1 day).**
`folders` subcommand + `--folder` switching with state refresh after the
view changes. Milestone: one run scans Inbox + Archiv + Gesendete
Elemente into per-folder output dirs.

**Phase 3 — polish + integration (~0.5 day).**
Unread-only flag, run manifest/stats, permission preflight with a helpful
error, README, Claude Code skill.

Total: ~4–5 focused days, est. 2–3k LOC. Risk is concentrated in
Phase 0; everything after it is low-uncertainty Go.

## Known risks

- **UI brittleness (inherent):** any Outlook update can move the tree.
  Mitigation: role-based navigation, `dump` tool for quick re-mapping,
  loud logging of tree-shape mismatches.
- **Body fidelity:** AXWebArea text extraction flattens formatting and
  may include quoted-reply noise. Acceptable for LLM ingestion.
- **Permissions:** the terminal (or whatever hosts the binary) needs
  Accessibility permission; scan requires Outlook running with the
  message-list view open. Preflight both and fail with instructions.
- **Locale drift:** timestamp parsing is best-effort; the raw string is
  always preserved so nothing is lost when parsing fails.
